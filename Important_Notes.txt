3. JIT (JUST-IN-TIME) COMPILATION IN JAVA
========================================================================================================================

A. WHAT IS BYTECODE?
--------------------
- When we compile a Java source file (.java) using javac, Java produces bytecode (.class).
- Bytecode is an intermediate set of instructions understood by the Java Virtual Machine (JVM).
- Bytecode is not the same as native machine code, which a processor executes directly.
- The JVM runs bytecode on the relevant operating system and hardware.

B. WHAT DOES THE INTERPRETER DO?
--------------------------------
- The interpreter executes bytecode instructions while the program is running.
- Interpreting instructions can involve extra work compared with executing native machine code.
- If all code were only interpreted, execution could be slower for programs that run for a long time.

C. WHAT IS JIT?
---------------
JIT stands for JUST-IN-TIME COMPILER.

- Modern JVMs use both interpretation and JIT compilation.
- While the program runs, the JVM collects information about how the code is being used.
- It identifies methods or sections of code that execute frequently.
- The JIT compiler can compile selected frequently executed code into native machine code.
- The processor can execute this compiled machine code directly.
- The compiled code can be reused, reducing the need to interpret that code again.

D. WHAT IS HOT CODE / A HOT SPOT?
---------------------------------
- Hot code means a method or section of code that executes frequently.
- A hot spot is a frequently executed part of the program that the JVM may choose to optimize.
- Cold code is code that executes infrequently.

Example:

    Method                 Number of executions
    -------------------------------------------
    login()                10 times
    calculate()            5,000,000 times
    processPayment()       20 times

Here, calculate() executes much more frequently. The JVM may identify it as hot code and compile it using the JIT compiler.

E. HOW DOES JIT WORK?
---------------------
1. javac compiles Java source code (.java) into bytecode (.class).
2. The JVM starts running the bytecode.
3. The JVM observes the program while it executes and gathers runtime information.
4. It identifies frequently executed methods or code sections.
5. The JIT compiler compiles selected hot code into native machine code.
6. The JVM can reuse the compiled code during later executions.

F. WHY CAN JAVA BECOME FASTER AFTER RUNNING FOR SOME TIME?
----------------------------------------------------------
- A Java application may take some time to warm up because the JVM starts, loads classes, executes code and performs JIT compilation.
- As the application runs, the JVM gathers information about its behavior.
- The JIT compiler can use that information to optimize frequently executed code.
- Therefore, long-running Java applications can become very fast and may achieve performance close to native applications such as C++ in some workloads.

IMPORTANT:
Java is not guaranteed to be as fast as C++. Actual performance depends on the application, algorithms, JVM, hardware and workload. JIT compilation does not guarantee that every method will be compiled.

G. WHAT IS HOTSPOT JVM?
-----------------------
- HotSpot is a widely used JVM implementation in OpenJDK and Oracle JDK.
- It uses runtime profiling and optimization techniques, including JIT compilation.
- It identifies frequently executed code (hot spots) and can optimize that code to improve performance.

H. INTERPRETER VS JIT COMPILER
------------------------------
    Interpreter:
    - Executes bytecode instructions.
    - Does not need to compile every method into native machine code.

    JIT Compiler:
    - Compiles selected frequently executed bytecode into native machine code.
    - Helps reduce repeated interpretation overhead for compiled code.

    Modern JVMs use interpretation and JIT compilation together.

J. IMPORTANT TERMS
------------------
- JVM: Java Virtual Machine; runs Java bytecode.
- Bytecode: Intermediate instructions produced by the Java compiler.
- Interpreter: Executes bytecode instructions.
- JIT: Just-In-Time compiler; compiles selected hot code into native machine code at runtime.
- Hot Code: Code that executes frequently.
- Runtime Profiling: Collecting information about program behavior while it runs.
- Native Machine Code: Instructions that the processor can execute directly.
- HotSpot: A widely used JVM implementation that uses runtime profiling and optimization techniques.

ONE-LINE SUMMARY:
JIT compilation improves Java performance by identifying frequently executed code and compiling selected parts into native machine code at runtime, allowing the processor to execute them more efficiently.

PART 2.3 — THE IF STATEMENT
============================

1. DECISION-MAKING WITH IF
--------------------------
- An if statement allows a program to execute code only when a condition is true.
- If the condition is false, Java skips the block and continues with the next statement.

    if (marks > 50) {
        System.out.println("Passed");
    }


2. COMPARISON OPERATORS
-----------------------
    >   : Greater than
    <   : Less than
    ==  : Equal to
    >=  : Greater than or equal to
    <=  : Less than or equal to
    !=  : Not equal to

- Comparison expressions return a boolean value: true or false.


3. ASSIGNMENT (=) VS COMPARISON (==)
------------------------------------
- = assigns a value to a variable.
- == compares two values.
- An assignment produces the assigned value, not a boolean.
- Java requires an if condition to produce a boolean.
- Therefore, if (marks = 95) causes an error because an int cannot be converted to boolean.


4. CURLY BRACES AND STATEMENT SCOPE
-----------------------------------
- With {}, all statements inside the braces belong to the if block.
- Without braces, if controls only the immediately following statement.
- Indentation does not determine which statements belong to the block.
- Always use curly braces, even for a single statement.


5. LOCAL VARIABLES AND DEFINITE ASSIGNMENT
------------------------------------------
- A local variable must be declared before it is used.
- Declaration introduces the variable's name and type; initialization gives it its first value.
- A local variable must be assigned before its value is read.
- Java checks every possible execution path during compilation.
- This rule is called definite assignment: Java must be able to prove that a local variable has been assigned on every possible path before it is used.

    int bonus;

    if (marks > 90) {
        bonus = 10;
    }

    System.out.println(bonus); // Compile-time error

- The condition could be false, leaving bonus without a value.


6. WAYS TO INITIALIZE A LOCAL VARIABLE SAFELY
---------------------------------------------
Method 1: Initialize it when declaring

    int bonus = 0;

    if (marks > 90) {
        bonus = 10;
    }

Method 2: Assign a value on every branch

    int bonus;

    if (marks > 90) {
        bonus = 10;
    } else {
        bonus = 0;
    }

- In both examples, bonus has a value before it is used.


7. IMPORTANT DISTINCTIONS
-------------------------
- Declaration introduces a variable; initialization gives it a starting value.
- A variable must be declared within a scope where it can be accessed.
- A local variable must be initialized before its value is read.
- An if condition must produce true or false.
- Braces control statement grouping; indentation does not.
- Compilation checks code validity; runtime is when the program executes.

8. Scope of variables
============================
- Local variable: the wall is the method.
- Private instance variable: the wall is the class.

REVISION — THE IF STATEMENT
===========================

1. IF STATEMENT
---------------
- Executes code only when its condition is true.
- If the condition is false, Java skips the block.

2. CONDITIONS AND COMPARISON OPERATORS
--------------------------------------
- The condition is written inside round brackets ().
- It must produce a boolean value: true or false.
- Comparison operators:
    >   Greater than
    <   Less than
    ==  Equal to
    >=  Greater than or equal to
    <=  Less than or equal to
    !=  Not equal to

3. ASSIGNMENT (=) VS COMPARISON (==)
------------------------------------
- = assigns or stores a value.
- == compares two values.
- if (x = 5) causes a type error because the condition
  produces an int instead of a boolean.

4. CURLY BRACES
---------------
- Without braces, if controls only the next statement.
- Java ignores indentation when determining code blocks.
- Always use braces to avoid unexpected execution.

5. ELSE STATEMENT
-----------------
- else defines the alternative path when the if condition
  is false.
- Exactly one of the if and else blocks executes.

6. BOUNDARY CONDITIONS
----------------------
- Always check values at the boundary.
- Example: 10 > 10 evaluates to false.
- Greater than (>) does not include equality.

7. DEFINITE ASSIGNMENT
----------------------
- Java checks every possible execution path at compile time.
- A local variable must have a value before it is used.
- Every possible path must assign a value.
- "Variable might not have been initialized" means Java
  cannot guarantee that the variable has a value.

8. TYPES OF COMPILE-TIME ERRORS
-------------------------------
- Syntax Error: Java cannot understand the code structure.
- Type Error: Java understands the code, but a value has
  an incompatible type.

IMPORTANT REMINDERS
-------------------
- if requires a boolean condition.
- = assigns; == compares.
- Braces define blocks, not indentation.
- Check boundary values carefully.
- Initialize local variables before using their values.

REVISION — THE FOR LOOP
=======================

1. FOR LOOP
-----------
- A for loop repeatedly executes its body while its condition is true.
- When the condition becomes false, the loop terminates.

2. THREE PARTS OF A FOR LOOP
----------------------------
Syntax:

    for (initialization; condition; iteration) {
        // Loop body
    }

- Initialization: Sets the starting value.
- Condition: Checks whether the loop should execute.
- Iteration: Updates the loop variable after each round.

3. EXECUTION ORDER
------------------
- Initialization executes only once.
- Condition is checked before every iteration.
- If true, the loop body executes.
- Iteration executes after the body.
- The process repeats until the condition becomes false.

Execution flow:

      start: int i = 0
       │
       ▼
  ┌─► check: i < 3 ? ── false ──► loop ends, carry on below it
  │        │ true
  │        ▼
  │    body: run the code in { }
  │        │
  │        ▼
  └─── step: i++

4. CONDITION IS CHECKED FIRST
-----------------------------
- The condition is checked before the first iteration.
- If it is false initially, the loop body executes zero times.

5. INCREMENT AND DECREMENT
--------------------------
- i++ is shorthand for i = i + 1.
- i-- is shorthand for i = i - 1.
- The iteration section can contain any valid calculation.

Examples:

    i = i + 3
    i = i - 3
    i = i * 2

6. < VS <= (BOUNDARY CONDITIONS)
--------------------------------
- i < 5  : Stops before reaching 5.
- i <= 5 : Includes 5.
- An off-by-one error occurs when a loop executes
  one iteration too many or too few.

7. VARIABLE SCOPE
-----------------
- A variable declared inside the for brackets is limited
  to the scope of that for loop.

    for (int i = 0; i < 5; i++) {
        System.out.println(i);
    }

- The variable i cannot be accessed outside its scope.

8. CURLY BRACES
---------------
- Without braces, the loop controls only the next statement.
- With braces, all statements inside the block repeat.
- Always use braces for clarity and safety.

9. VERIFY EVERY ITERATION
-------------------------
- Do not check only the final output or total.
- Compare every printed line with the expected output.
- A program can produce a correct total while containing
  an error in individual iterations.

IMPORTANT REMINDERS
-------------------
- Initialization runs once.
- Condition is checked before every iteration.
- Iteration runs after the loop body.
- A false initial condition means zero iterations.
- < excludes the boundary; <= includes it.
- Check every line of output.
